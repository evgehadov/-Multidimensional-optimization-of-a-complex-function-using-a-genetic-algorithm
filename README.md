# Лабораторная работа №1. Генетический алгоритм и обобщённая функция Леви (вариант 7)

Сравнение генетического алгоритма (ГА) с вещественным кодированием и случайного поиска
на задаче минимизации обобщённой функции Леви при одинаковом бюджете вычислений целевой функции.

## 1. Постановка задачи

Размерность: `d = 5 + (V mod 6) = 5 + (7 mod 6) = 6`. Вектор решения `x = (x_1, ..., x_6)`,
ограничения `-10 <= x_i <= 10`.

```
w_i = 1 + (x_i - 1) / 4

f(x) = sin²(π·w_1)
     + Σ_{i=1..d-1} (w_i - 1)² · [1 + 10·sin²(π·w_i + 1)]
     + (w_d - 1)² · [1 + sin²(2π·w_d)]
```

В сумме стоит квадрат синуса от всего аргумента `π·w_i + 1`, а не `sin²(π·w_i) + 1`.
Глобальный минимум: `x* = (1, 1, 1, 1, 1, 1)`, `f(x*) = 0`. Оптимум известен только для проверки
корректности (тесты); алгоритмы его не используют: ни при инициализации, ни при поиске.

## 2. Эксперименты

Каждый метод выполняется 20 независимых запусков по 6000 вычислений целевой функции.

| Эксперимент | Метод | Масштаб мутации σ |
|---|---|---|
| A | ГА, базовый | 2 (0.1·(u − l)) |
| B | ГА, повышенный масштаб мутации | 4 (0.2·(u − l)) |
| C | Случайный поиск | не применимо |
| D | ГА, адаптивная мутация | линейно от 2 до 0.1 |

Общие параметры ГА: размер популяции 60, турнир k = 3, вероятность скрещивания 0.9,
вероятность мутации координаты 1/6, бюджет 6000. B отличается от A только значением σ,
D отличается от A только расписанием σ. Размер популяции, отбор, скрещивание,
вероятность мутации и бюджет во всех трёх одинаковы.

Планируемый суммарный бюджет: 4 · 20 · 6000 = 480000 вычислений.

## 3. Генетический алгоритм

- **Кодирование:** особь это вектор из 6 вещественных чисел.
- **Инициализация:** все координаты независимо из `U(-10, 10)`. Оптимум в популяцию не добавляется.
- **Отбор:** турнир из 3 участников, выбираемых с возвращением (одна особь может попасть
  в турнир несколько раз). Побеждает участник с наименьшим `f`. При равенстве значений
  побеждает тот, кто был выбран раньше. Популяция при отборе не изменяется.
- **Скрещивание:** арифметическое, с вероятностью 0.9. Для каждой координаты свой
  коэффициент `α_i ~ U(0, 1)`:
  `c1_i = α_i·p1_i + (1 − α_i)·p2_i`, `c2_i = α_i·p2_i + (1 − α_i)·p1_i`.
  Без скрещивания потомки это копии родителей. Потомки создаются парами до ровно 60 особей.
  Родители не изменяются.
- **Мутация:** каждая координата независимо с вероятностью 1/6 получает добавку
  `N(0, σ²)`, где σ это стандартное отклонение. Затем проекция на границы
  `x' = min(10, max(-10, x'))`.
- **Элитизм:** лучшая особь предыдущей популяции заменяет худшего потомка, если она
  строго лучше него. Целевая функция для элитной копии не вычисляется повторно.
  Глобально лучшее решение запуска хранится отдельно и не может ухудшиться.

### Учёт бюджета

Начальная популяция: 60 вычислений. Каждое из 99 поколений потомков: 60 вычислений.
`60 + 99·60 = 6000`. Все вызовы целевой функции идут через счётчик
(`EvaluationCounter` в `objective.py`), в конце запуска проверяется, что фактически
выполнено ровно столько вычислений, сколько задано бюджетом. Статистика и графики
функцию не вызывают.

### История запуска

ГА записывает историю для начальной популяции (поколение 0) и каждого поколения 1..99,
то есть 100 записей: номер поколения, накопленное число вычислений (60, 120, ..., 6000),
лучшее, среднее и худшее значение в текущей популяции и лучшее значение за весь запуск
(`best_so_far`). Случайный поиск записывает `best_so_far` после каждого вычисления (6000 записей).

## 4. Случайный поиск (эксперимент C)

6000 независимых равномерных выборок из `U(-10, 10)^6`. Все кандидаты генерируются до
первого вычисления функции, поэтому значения функции не влияют на новые точки. Отбора,
скрещивания и мутации нет.

## 5. Адаптивная мутация (эксперимент D)

Масштаб мутации линейно уменьшается от `σ_max = 2` до `σ_min = 0.1`:

```
σ(t) = σ_max − (t / T) · (σ_max − σ_min),   t = 0..98,   T = 98
```

`t` это номер поколения потомков минус один, `T = 98` это число поколений минус один.
Значение определяется в начале поколения, до мутации. Поэтому первое поколение потомков
идёт с `σ = 2` (начало расписания), а последнее, 99-е, с `σ = 0.1` (конец расписания).
Вероятность мутации координаты остаётся 1/6.

**Ожидаемые преимущества.** Большой шаг вначале даёт широкий обзор области, когда
популяция разбросана по всему кубу. Малый шаг в конце позволяет доводить уже найденные
решения до точности, на которую при σ = 2 мутация не способна: шаг порядка двух единиц
слишком груб вблизи минимума. Расписание не требует дополнительных вычислений функции.

**Возможные ограничения.** Расписание не зависит от хода поиска: оно не заметит, что
популяция уже застряла в локальном минимуме (у функции Леви их много), и не вернёт
шаг, если он оказался слишком маленьким. Оно привязано к заранее известному числу
поколений. Значения `σ_max` и `σ_min` выбраны заданием и не подбирались. Если решение
найдено раньше конца расписания, оставшиеся поколения идут с неоптимальным шагом.
Вероятность мутации координаты остаётся постоянной, поэтому малый шаг в конце не
компенсируется более частыми мутациями. Что из этого проявится на самом деле,
покажут только результаты эксперимента.

## 6. Воспроизводимость

- Запуск `i` (i = 1..20) использует seed `202600 + i`, то есть от 202601 до 202620.
- Каждый запуск каждого метода создаёт собственный генератор `numpy.random.default_rng(seed)`.
  Общего изменяемого генератора нет, поэтому результат метода не зависит от того,
  в каком порядке и сколько других методов запускалось.
- При тех же параметрах и seed на той же программной среде результаты воспроизводятся.
- Одинаковый seed в разных методах сам по себе не гарантирует одинаковых случайных
  последовательностей. Наблюдение для нашей реализации: у A, B и D генератор первым
  делом создаёт начальную популяцию, поэтому при одном seed их начальные популяции
  совпадают. Это следствие порядка вызовов в коде, а не свойство seed. После начальной
  популяции сценарии расходятся.

## 8. Установка и запуск

Все команды выполняются из корня проекта. Окружение разработки: Python 3.14.2,
numpy 2.5.4, matplotlib 3.11.2, pytest 9.1.1.

```
source .venv/bin/activate
pip install -r requirements.txt
```

| Команда | Что делает |
|---|---|
| `python main.py quick` | быстрый пробный прогон (популяция 10, бюджет 60, 3 запуска), результаты в `results/quick`; числа в отчёт не идут |
| `python main.py test` | автоматические тесты (то же, что `python -m pytest -q`) |
| `python main.py full` | полный эксперимент: 4 метода x 20 запусков x 6000 вычислений, результаты в `results` |
| `python main.py plots` | перестроить графики из сохранённых результатов, ничего не пересчитывая |

Параметры для `quick` и `full`:

| Аргумент | Значение по умолчанию (full) |
|---|---|
| `--results-dir` | `results` (для quick `results/quick`) |
| `--runs` | 20 (для quick 3) |
| `--base-seed` | 202600 (seed запуска i равен base-seed + i) |
| `--population-size` | 60 (для quick 10; для full не меньше 30) |
| `--budget` | 6000 (для quick 60) |
| `--success-threshold` | нет значения по умолчанию |
| `--overwrite` | разрешить перезапись существующих результатов |

Бюджет должен равняться `population_size · (1 + число поколений)`, иначе ГА не может
израсходовать его ровно, и программа остановится с сообщением об ошибке до расчёта.
Масштаб мутации и остальные параметры ГА через командную строку не меняются: B и D по
заданию отличаются от A ровно одним параметром. Если в каталоге уже есть результаты,
`full` остановится, пока не добавлен `--overwrite`. Исключение: каталог `results/quick`
пробный прогон перезаписывает без флага.

Коды завершения: 0 успех, 2 ошибка аргументов или данных.
Тесты не запускают полный эксперимент: они работают на малых бюджетах.

## 10. Статистический анализ

По итоговым значениям запусков каждого метода считаются: минимум, максимум,
среднее арифметическое, медиана, стандартное отклонение, число запусков,
фактическое число вычислений на запуск, время выполнения (среднее и суммарное).

- Стандартное отклонение **выборочное**, делитель `n − 1`. При одном запуске оно не определено (NaN).
- Время измеряется вокруг одного запуска и зависит от машины.
- **Порог успеха не задан.** Любое число было бы выдуманным без обоснования, поэтому
  значения по умолчанию нет, и доля успешных запусков по умолчанию не считается.
  Если указать `--success-threshold`, успехом считается запуск, итоговое значение которого
  не больше порога, и в таблице появляется столбец `success`.
- Округление применяется только при выводе таблицы на экран. В файлах данные не округляются.

## 11. Результаты эксперимента

Полный запуск `python main.py full`: 4 метода, по 20 независимых запусков (seed 202601–202620),
6000 вычислений целевой функции на запуск. Значения округлены до трёх значащих цифр, точные числа
в `results/summary.csv` и `results/raw_runs.csv`. Стандартное отклонение выборочное (делитель n − 1).

| Метод | Минимум | Максимум | Среднее | Медиана | Std | Среднее время запуска, с |
|---|---|---|---|---|---|---|
| A (ГА, σ = 2) | 3.39e-4 | 3.08e-3 | 1.27e-3 | 1.09e-3 | 7.47e-4 | 0.116 |
| B (ГА, σ = 4) | 1.26e-4 | 7.47e-3 | 3.00e-3 | 2.83e-3 | 2.08e-3 | 0.115 |
| C (случайный поиск) | 0.823 | 4.39 | 2.51 | 2.72 | 0.933 | 0.0694 |
| D (ГА, σ от 2 до 0.1) | 7.25e-6 | 1.70e-4 | 6.22e-5 | 5.01e-5 | 4.63e-5 | 0.116 |

Суммарное время работы всех запусков алгоритмов около 8.3 с (время зависит от компьютера).
Порог успеха не задан, поэтому доля успешных запусков не считается.

### Что видно из таблицы

1. **ГА намного лучше случайного поиска.** Худший запуск среди всех ГА (B, 7.47e-3) лучше
   лучшего запуска случайного поиска (0.823) больше чем в 100 раз. Среднее значение
   случайного поиска примерно в 2000 раз больше среднего значения A.
2. **Адаптивная мутация (D) дала лучший результат.** Среднее D (6.22e-5) примерно в 20 раз
   меньше среднего A (1.27e-3). Худший запуск D (1.70e-4) лучше лучшего запуска A (3.39e-4):
   диапазоны значений A и D не пересекаются.
3. **Увеличенный масштаб мутации (B) в среднем хуже базового.** Среднее и медиана B выше,
   чем у A (3.00e-3 против 1.27e-3 и 2.83e-3 против 1.09e-3), разброс больше
   (std 2.08e-3 против 7.47e-4). Но лучший запуск B (1.26e-4) лучше лучшего запуска A,
   и диапазоны пересекаются. Поэтому речь идёт о тенденции по 20 запускам, а не о том,
   что B проигрывает в каждом запуске. Формальный статистический тест не проводился.
4. **Точный оптимум не найден ни в одном запуске.** Лучшее значение за весь эксперимент
   7.25e-6 (D), глобальный минимум равен 0.
5. **Время.** В нашей реализации ГА тратит на запуск примерно 0.116 с, случайный поиск
   0.0694 с: операторы ГА выполняются в цикле на Python, а случайный поиск генерирует все точки одним вызовом.

### Как это связано с ожиданиями

Эксперимент D отличается от A только расписанием σ, поэтому с учётом разброса запусков
разницу между ними можно относить на счёт расписания. Это согласуется с ожидаемым
преимуществом из раздела 5: малый шаг в конце позволяет точнее приблизиться к минимуму,
чем фиксированное σ = 2. Худший результат B согласуется с предположением, что при σ = 4
шаг слишком груб вблизи минимума. Оба объяснения это гипотезы: сам механизм эксперимент
не измерял, а вывод относится к конкретным значениям σ и расписанию из задания.
Динамика по числу вычислений показана на графиках `results/convergence_ga.png` и
`results/ga_vs_random_search.png`, распределение итоговых значений на `results/final_values_boxplot.png`.

## 12. Ограничения

- Бюджет должен раскладываться на целое число поколений (см. раздел 8).
- Среднее арифметическое на логарифмической шкале сильно зависит от самых плохих запусков,
  поэтому среднее на графике не показывает типичный запуск. Для этого есть медиана
  в таблице и точки на boxplot.
- Расписание σ в эксперименте D зафиксировано заданием и не подбиралось, поэтому
  результат D говорит о качестве этого расписания, а не о возможностях адаптивной мутации вообще.
- Для каждого метода по 20 запусков: этого достаточно для описательного сравнения,
  но не для строгих выводов о малых различиях.
- Результаты воспроизводятся на той же программной среде (Python и версии пакетов
  из `requirements.txt`). На другой версии numpy числа могут отличаться.
- Время работы зависит от компьютера.
